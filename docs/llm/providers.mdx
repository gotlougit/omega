## Provider Trait

All providers implement `LlmProvider`:

```rust
use picrust::llm::{LlmProvider, AnthropicProvider, GeminiProvider, OpenAIProvider};

let anthropic: Arc<dyn LlmProvider> = Arc::new(AnthropicProvider::from_env()?);
let gemini: Arc<dyn LlmProvider> = Arc::new(GeminiProvider::from_env()?);
let openai: Arc<dyn LlmProvider> = Arc::new(OpenAIProvider::from_env()?);

let agent = StandardAgent::new(config, openai);
```

## AnthropicProvider

```rust
use picrust::llm::AnthropicProvider;

// From env vars (ANTHROPIC_API_KEY, ANTHROPIC_MODEL)
let llm = AnthropicProvider::from_env()?;

// Explicit key and model
let llm = AnthropicProvider::new("sk-ant-...")?
    .with_model("claude-sonnet-4-5@20250929");

// Custom max tokens
let llm = AnthropicProvider::from_env()?
    .with_max_tokens(8192);
```

### Auth Refresh

```rust
use picrust::llm::{AuthProvider, AuthConfig};

struct MyAuthProvider;

#[async_trait]
impl AuthProvider for MyAuthProvider {
    async fn get_auth(&self) -> anyhow::Result<AuthConfig> {
        let token = refresh_jwt_token().await?;
        Ok(AuthConfig::new(token))
    }
}

let llm = AnthropicProvider::with_auth_provider_boxed(Arc::new(MyAuthProvider));
```

## OpenAIProvider

Supports both OpenAI Chat Completions and the [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses). Chat Completions is the default; set `OPENAI_API_TYPE=responses` to opt into Responses.

```rust
use picrust::llm::{OpenAIApiType, OpenAIProvider};

// From env vars (including OPENAI_API_TYPE)
let llm = OpenAIProvider::from_env()?;

// Explicit Responses API provider using Codex OAuth credentials
let llm = OpenAIProvider::new("codex-oauth-access-token")
    .with_api_type(OpenAIApiType::Responses)
    .with_account_id("chatgpt-account-id")
    .with_model("your-codex-model")
    .with_max_tokens(Some(4096));
```

### Environment Variables

| Variable | Required | Default |
|---|---|---|
| `OPENAI_API_TYPE` | No | `chat-completions` |
| `OPENAI_API_KEY` | Chat Completions only | — |
| `OPENAI_MODEL` | No | `gpt-4o` |
| `OPENAI_REASONING_EFFORT` | No | Inferred from the request, or upstream default |
| `OPENAI_BASE_URL` | No | `https://api.openai.com/v1/chat/completions` |
| `OPENAI_RESPONSES_ACCESS_TOKEN` | Responses only | — |
| `OPENAI_RESPONSES_ACCOUNT_ID` | Responses only | — |
| `OPENAI_RESPONSES_REFRESH_TOKEN` | No | Automatic refresh disabled |
| `OPENAI_RESPONSES_ENV_FILE` | No | Refreshed tokens remain in memory only |
| `OPENAI_RESPONSES_OAUTH_CLIENT_ID` | No | Codex OAuth client ID |
| `OPENAI_RESPONSES_OAUTH_TOKEN_URL` | No | `https://auth.openai.com/oauth/token` |
| `OPENAI_RESPONSES_BASE_URL` | No | `https://chatgpt.com/backend-api/codex/responses` |
| `OPENAI_MAX_TOKENS` | No | Upstream default |

### Codex Credentials and Custom Base URL

Responses mode authenticates with the OAuth access token and ChatGPT account ID
from Codex credentials. Pass the values to `omega-loop`; the crate does not read
the Codex credentials file itself. The access token is sent as a bearer token and
the account ID is sent in `ChatGPT-Account-ID`.

When a refresh token is configured, omega refreshes an access token within five
minutes of its JWT expiry or after a `401 Unauthorized` response, then retries the
request once. The current tokens are updated in memory immediately. If
`OPENAI_RESPONSES_ENV_FILE` is set, access and rotated refresh tokens are also
written back atomically while preserving the file's permissions:

```bash
export OPENAI_API_TYPE="responses"
export OPENAI_RESPONSES_ACCESS_TOKEN="..."
export OPENAI_RESPONSES_ACCOUNT_ID="..."
export OPENAI_RESPONSES_REFRESH_TOKEN="..."
export OPENAI_RESPONSES_ENV_FILE="/var/lib/clanker/omega/.env"
export OPENAI_MODEL="your-codex-model"
export OPENAI_REASONING_EFFORT="medium"
# Optional override:
export OPENAI_RESPONSES_BASE_URL="https://chatgpt.com/backend-api/codex/responses"
```

The env file and its parent directory must be writable by `omega-loop` for
atomic replacement. Keep it mode `0600` and outside the Nix store. Do not let
another Codex process refresh a stale copy of the same rotating refresh token;
use this env file as the authoritative credential store once omega owns refresh.

Or in code:

```rust
let llm = OpenAIProvider::new("codex-oauth-access-token")
    .with_api_type(OpenAIApiType::Responses)
    .with_account_id("chatgpt-account-id")
    .with_model("your-codex-model");
```

### Dynamic Auth (Codex OAuth / Proxy / JWT)

```rust
use picrust::llm::{AuthConfig, OpenAIApiType, OpenAIProvider};

let llm = OpenAIProvider::with_auth_provider(|| async {
    let token = my_auth_service.get_fresh_token().await?;
    let account_id = my_auth_service.chatgpt_account_id().await?;
    Ok(AuthConfig::with_base_url(
        token,
        "https://chatgpt.com/backend-api/codex/responses",
    )
    .with_account_id(account_id))
})
.with_api_type(OpenAIApiType::Responses);
```

### Notes

- **Thinking / reasoning**: In Responses mode, `ThinkingConfig` maps to `reasoning.effort` (`low`, `medium`, `high`) and reasoning summaries are streamed as thinking blocks. Chat Completions continues to surface compatible `reasoning_content` deltas when a gateway emits them.
- **Explicit effort**: `OPENAI_REASONING_EFFORT` accepts `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max` and overrides the effort inferred from `ThinkingConfig`. Model support varies.
- **Prompt caching**: OpenAI does not use Anthropic-style prompt caching. Disable it in `AgentConfig` to avoid unnecessary overhead:
  ```rust
  let config = AgentConfig::new().with_prompt_caching(false);
  ```
- **Tool schema**: Tools are translated to OpenAI function definitions automatically. Optional parameters are supported (strict mode is disabled).

## SwappableLlmProvider

Change LLM at runtime:

```rust
use picrust::llm::SwappableLlmProvider;

let swappable = Arc::new(SwappableLlmProvider::new(anthropic_provider));

// Use with agent
let agent = StandardAgent::new(config, swappable.clone());

// Swap provider later
swappable.swap(gemini_provider).await;
```

## Extended Thinking

Supported by all three providers:

```rust
use picrust::llm::ThinkingConfig;

let config = AgentConfig::new()
    .with_thinking(16000);  // Budget in tokens

// Or with config object
let config = AgentConfig::new()
    .with_thinking_config(ThinkingConfig::enabled(32000));
```

### Provider Differences

**AnthropicProvider**: Uses the budget directly as thinking tokens.

**GeminiProvider**: Automatically converts budget to the appropriate format:
- **Gemini 3 models**: Budget maps to thinking levels (`minimal`, `low`, `medium`, `high`)
  - `0-512` → `minimal`
  - `513-2048` → `low`
  - `2049-8192` → `medium`
  - `8193+` → `high`
- **Gemini 2.5 models**: Uses numeric budget directly

**OpenAIProvider**: Budget maps to `reasoning.effort` and automatically requests reasoning summaries:
- `0-2048` → `low`
- `2049-8192` → `medium`
- `8193+` → `high`

Reasoning summaries are streamed as `ContentBlock::Thinking` blocks, and reasoning tokens are tracked in `Usage.thoughts_token_count`.

The conversion is automatic based on the provider, so you use the same `.with_thinking()` API for all three providers.

## Message Types

```rust
use picrust::llm::{Message, ContentBlock};

let msg = Message::user("Hello");
let msg = Message::assistant("Hi");

// With blocks
let msg = Message::user_with_blocks(vec![
    ContentBlock::text("Analyze this"),
    ContentBlock::image(image_data, "image/png"),
]);
```

## Content Blocks

```rust
match &message.content {
    MessageContent::Blocks(blocks) => {
        for block in blocks {
            match block {
                ContentBlock::Text { text } => {},
                ContentBlock::ToolUse { id, name, input } => {},
                ContentBlock::ToolResult { tool_use_id, content, is_error } => {},
                ContentBlock::Thinking { thinking, .. } => {},
                ContentBlock::Image { source } => {},
                ContentBlock::Document { source, .. } => {},
                _ => {}
            }
        }
    }
    _ => {}
}
```
